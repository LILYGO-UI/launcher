# LILYGO UI 设计规范

本文规定 LILYGO UI Launcher、AppKit 以及独立 LILYGO UI 应用的设计要求，统一响应式
布局、颜色、字体、字号和中西文混排规则；新增或修改界面时必须遵守本文。

## 字体家族

| 文本内容 | 字体 | 说明 |
| --- | --- | --- |
| 西文字母、数字和西文标点 | [Inter](https://rsms.me/inter/) | 默认使用 Regular 字重 |
| 简体中文及中文标点 | [思源黑体](https://fonts.adobe.com/fonts/source-han-sans-simplified-chinese)（Source Han Sans CN） | 默认使用 Normal 字重 |

包含中西文的同一段文本必须直接使用 AppKit 提供的复合字体，或使用以该复合字体
作为 fallback 的应用增量字体。AppKit 复合字体以 Inter 显示西文字母、数字和西文
标点，以思源黑体显示中文，并统一基线、字号和 fallback。不要为了混排而拆分标签，
也不要依赖操作系统的默认字体回退。

图标字形使用 AppKit 运行时字体链中的 Font Awesome 字形，不改变正文的字体选择规则。

## 字号层级

只使用 AppKit 已提供的以下字号，不在应用内建立另一套字号或直接引用字体文件：

| 字号 | LVGL API | 推荐用途 |
| --- | --- | --- |
| 14 px | `lilygo_ui_font_get(14)` | 辅助信息、紧凑标签 |
| 22 px | `lilygo_ui_font_get(22)` | 正文、按钮、列表项和状态栏 |
| 28 px | `lilygo_ui_font_get(28)` | 小标题、重点数值 |
| 36 px | `lilygo_ui_font_get(36)` | 页面标题、主要数值 |
| 48 px | `lilygo_ui_font_get(48)` | 时间、结果等需要突出显示的内容 |

相同信息层级在不同页面中应使用相同字号。缩小字号不能作为修复溢出的首选方案；
应先精简文案、调整布局或按产品要求使用截断和换行。

## 响应式布局

新增或修改 UI 时必须使用响应式设计技术，使同一套界面能够适应目标设备的不同
显示尺寸、宽高比和横竖屏方向。不得只针对单一固定分辨率排列控件，也不得通过
复制整套页面来分别维护横屏、竖屏、phone 或 desktop 布局。

LVGL 界面应优先使用 Flex 或 Grid layout 组织控件，并结合百分比尺寸、
`LV_SIZE_CONTENT`、最小/最大尺寸、对齐、间距和滚动容器分配可用空间。固定像素值
只用于有明确设计约束的尺寸，例如触控目标下限、图标尺寸、边框和设计 token；
不得依赖大量绝对坐标实现页面主体布局。

连续的尺寸变化应由 layout 自动处理。导航方向、栏数、内容优先级或交互方式发生
结构性变化时，应根据容器的实际可用宽高设置明确断点，并在尺寸变化后重新应用布局。
断点依据显示几何、输入方式和会话能力确定，不能只依据 CPU 架构或设备型号。
可复用组件必须以父容器的可用尺寸为响应依据，不能假设自己始终占满 display。
运行时尺寸或方向变化触发布局更新时，更新过程必须可重复执行，并保留当前业务状态、
焦点、滚动位置和用户输入；不得把重建整个页面作为常规的尺寸适配方式。

Launcher 分页标记的视觉宽度为 8 px，当前页为 24 px，但每个标记必须保留独立的
`40x40` 命中区域；分页较多时命中区域容器必须横向滚动，并自动保持当前页可见。

响应式布局必须保证：

- 文本按产品要求换行或截断，不与相邻内容重叠，也不通过任意缩小字号来适配；
- 主要操作在各目标尺寸下始终可见、可达，并保持足够的触控或指针命中区域；
- 内容增多、文案变长或字体回退时，容器能够扩展、重排或滚动，不发生裁切；
- phone、desktop、横屏和竖屏可以改变呈现方式，但保持同一应用身份和业务状态；
- 在支持的最小、典型和最大视口以及横竖屏切换后完成渲染与交互验证。

## LVGL 实现

LVGL 代码必须包含 `<cm0/typography.h>` 并使用公共字体 API：

```c
#include <cm0/typography.h>

lv_obj_set_style_text_font(label, lilygo_ui_font_get(22), 0);
```

必须在 `lv_init()` 后一次性取得所需字体并确认返回值非空，再创建任何显示文本的
对象。字体对象及 fallback 链由 AppKit 管理，Launcher 不修改也不释放单个字体。

不得在公共 UI 中新增 `lv_font_montserrat_*` 引用。通常应直接使用 AppKit 字体 API，
这样可以保证 Launcher 与各应用的字形、基线和 fallback 一致。仅当独立应用使用了
AppKit 运行时字体未包含的应用专有字形时，才可按“应用专有字形”一节创建私有增量字体。

Launcher、AppKit 和独立应用都直接使用 LVGL API 创建界面。View 代码必须直接调用
上述字体 API，或引用以同字号 AppKit 字体为 fallback 的应用增量字体；不能
复制、改名或重新生成一份完整的 AppKit 字体数据。

## 应用专有字形

仅当 AppKit 运行时字体确实缺少应用所需字形时，独立应用才可在 `assets/fonts/`
提供应用专用的 TTF、OTF 或 WOFF 字体。不得复制或重新打包 AppKit 已提供的 Inter、
Source Han Sans CN 或 Font Awesome 字体。应用专用字体必须满足：

- 通过 `lv_freetype_font_create()` 按当前 UI 字号在运行时加载；
- 将应用专用字体作为引用它的 LVGL 对象的主字体，并将其 `fallback` 设为同字号的
  `lilygo_ui_font_get(size)` 结果；
- 不得修改 `lilygo_ui_font_get()` 返回的共享字体对象或它的 fallback 链；
- 字体对象的生命周期必须不短于引用它的 LVGL 对象；移除所有引用后，必须通过
  `lv_freetype_font_delete()` 释放；
- 字体文件必须通过应用的安装和打包规则部署到稳定的运行时路径；
- 可通过可重复的子集化流程仅保留所需字形以减小安装体积，但不得手工修改生成的
  字体文件。

新增应用专用字体时还必须记录字体来源、版权和许可证，并将相应许可文件纳入包。

## Ardot 实现

Ardot 中必须使用准确的字体家族名称 `Inter` 和 `Source Han Sans CN`。不含 CJK
字符的文本选择 `Inter`；包含中文的文本选择 `Source Han Sans CN`。字号应与上表
的层级保持一致。

## 字符集与运行时字体

设备通过共享的 `lilygo-ui-appkit-dev` 包安装源码 SDK、完整运行时字体和许可证；AppKit
及 LVGL 代码静态链接到各应用。新增中文文案无需生成位图
子集；应用应直接使用 AppKit 字体，并在设备构建或 UI 渲染测试中确认没有缺字、
错误回退或文字裁切。仅运行时字体不包含的应用专有字形才使用上一节所述的私有
增量字体。应用不得复制或再次打包完整字体文件。

## 授权与分发

Inter、思源黑体和 Font Awesome 字体均按 SIL Open Font License 1.1
分发。它们是受版权保护的 OFL 授权资产，不能描述为“无版权字体”，也不能单独
销售。任何包含这些字体的 SDK 或二进制分发都必须同时保留：

- AppKit 仓库的 `fonts/licenses/NOTICE.md`
- AppKit 仓库的 `fonts/licenses/OFL-1.1.txt`

## 设计验收清单

- 页面背景颜色为 `#F2F2F7`，透明度为 `100%`。
- 西文、数字和西文标点显示为 Inter；中文显示为思源黑体。
- 中西文混排使用同一 AppKit 复合字体或以其为 fallback 的增量字体，基线和字号一致。
- 界面通过 `lilygo_ui_font_get()` 使用规定的五档字号。
- 页面使用 Flex/Grid 等响应式布局技术，不依赖单一分辨率或大量绝对坐标。
- 最小、典型和最大目标视口以及横竖屏下均无重叠、裁切或不可达操作。
- 容器尺寸或方向动态变化后，布局正确重排且业务状态、焦点和用户输入保持不变。
- 新增中文字符已通过 AppKit 运行时字体链验证；缺失的应用专有字形使用 supplemental
  font，并 fallback 到同字号 AppKit 字体。
- 字体在目标分辨率、横竖屏及明暗主题下没有溢出、遮挡或缺字。
- 字体授权文件随所有包含字体的分发物一起分发。
