# T-Display-K230

The launcher uses the same `LilyGoUI` SDK as CM0. The K230 profile supplies DRM
software rendering, RGB565 staging scanout and automatic Goodix input discovery.
See the AppKit `docs/k230.md` for the supported Linux BSP and platform details.

See [the board validation record](k230-validation.md) for tested firmware,
interaction results, benchmark measurements and known BSP limitations.

## Build

On the Linux build host, install `lilygo-lpm` and build the upstream
T-Display-K230 Linux image first. The SDK must match the board image. Then:

```sh
./tools/build-k230.sh \
  /work/t-display-k230/k230_linux_sdk/output/k230_canmv_t_display_rm69a10_defconfig \
  /work/lilygo-ui-appkit \
  /work/lilygo-ui-template
```

The third argument is optional and names an independently built application;
the launcher never adds that application's sources or tests to its CMake tree.
Each repository receives its own `build/k230-cross` and `dist/k230` artifacts.
The helper refuses to reuse a cache from a different SDK/toolchain; move that
build directory aside before changing SDKs.
The AppKit source must contain the K230 profile. When using `cmake --preset
k230-cross` directly, update the pinned source submodule first or pass
`-DLilyGoUI_DIR=/work/lilygo-ui-appkit` explicitly.

The stock image is Buildroot, so artifacts are tar archives rather than Debian
packages. Install the AppKit archive once for shared fonts/licenses and source
SDK, then the launcher and desired independent application archives. Keep a
backup of any previous LILYGO UI versions when replacing them. The archives
retain stable `/usr/bin/lilygo-ui-*` and `cc.lilygo.ui.*` identities.

The stock BusyBox `tar` does not enable `-z`; its Python supports gzip archives.
For example, extract a verified package into a staging directory before testing:

```sh
python3 -c 'import tarfile; tarfile.open("package.tar.gz").extractall("/tmp/lilygo-ui-test", filter="data")'
```

Set `LILYGO_UI_FONT_DIR` to the staging `usr/share/lilygo-ui/fonts` directory and
pass the staging `usr/share/launcher/apps` as `--app-dir` when testing without a
system installation. Relative manifest paths also resolve inside that prefix.

## Network startup

The stock K230 shell owns Wi-Fi reconnection. `S45lilygo-ui-network` moves that
work into a separate SysV service so SSH and network access survive a reboot
without the old graphical shell. The stock BSP already supplies Python 3,
`wpa_supplicant`, `wpa_cli`, `ip`, and `udhcpc`.

Before stopping the stock shell, migrate its saved connection on the target:

```sh
python3 /usr/lib/lilygo-ui-launcher/k230-network.py prepare
```

The helper uses the live `/tmp/k230_wifi_ui.conf` or saved
`/root/app/k230_phone_ui/wifi_profiles.conf` and writes
`/etc/lilygo/ui/k230-wifi.conf` with mode 0600. SSIDs are hex encoded and WPA
passphrases are converted to PSKs; credentials are never printed or passed as
command arguments. Existing administrator configuration and the stock
`wifi.enabled=0` preference are respected. A missing saved profile must be
resolved before relying on wireless SSH after reboot.

The asynchronous service waits for the interface and association, then starts
the BSP DHCP client with lease renewal. Existing network managers are preserved.
Logs are in `/var/log/lilygo-ui-network.log`; `status` reports whether a manager
or owned worker is active, not a guarantee of Internet access. Verify an IP
address and SSH connection separately. Only tracked processes with matching
Linux start times are stopped by this service.

## Sessions and services

`LAUNCHER_SYSTEM_SESSION=OFF` uses the account selected by init/login and opens
the home screen immediately. It does not call PAM, create users, run Raspberry
Pi first-boot setup or change process credentials. Account lock/logout actions
are hidden; the CM0 PAM session remains the default for CM0 device builds.
File sharing keeps its existing non-root ownership requirement and reports an
unavailable state in the stock root kiosk session.

K230 installs `/etc/init.d/S99lilygo-ui-launcher` and administrator settings in
`/etc/lilygo/ui/launcher.conf`. The service captures stdout/stderr in
`/var/log/lilygo-ui-launcher.log` (configurable with `LOG_FILE`) and supports
`status` as well as start/stop/restart. Only one direct DRM shell can be active. To
switch from the upstream shell after installing and checking the binaries:

```sh
/usr/libexec/lilygo-ui-appkit/check-k230-target.sh
python3 /usr/lib/lilygo-ui-launcher/k230-network.py prepare
/etc/init.d/S99zz_k230_phone_ui stop
mv /etc/init.d/S99zz_k230_phone_ui /etc/init.d/disabled-k230_phone_ui
/etc/init.d/S45lilygo-ui-network start
/etc/init.d/S99lilygo-ui-launcher start
```

The new service refuses to start while the upstream shell is enabled or
running. The stock `rcS`/`rcK` execute every `S??*` entry without checking its
executable bit; move disabled scripts outside that pattern instead of merely
using `chmod -x`. For deployments made through an installation backup, use its
`restore-original-ui.sh`. To restore a manual switch made with the commands
above:

```sh
/etc/init.d/S99lilygo-ui-launcher stop
mv /etc/init.d/S99lilygo-ui-launcher /etc/init.d/disabled-lilygo-ui-launcher
mv /etc/init.d/S45lilygo-ui-network /etc/init.d/disabled-lilygo-ui-network
mv /etc/init.d/disabled-k230_phone_ui /etc/init.d/S99zz_k230_phone_ui
/etc/init.d/S99zz_k230_phone_ui start
```

For a foreground test after stopping the active shell, run:

```sh
/usr/bin/lilygo-ui-launcher --display drm --input auto --orientation portrait
# Or run the same executable with --orientation landscape.
```

Test a separately installed application such as `cc.lilygo.ui.Template` from
the home screen and return using its home gesture. The launcher passes display,
input, geometry and orientation arguments to the application and reacquires the
display after it exits. The original shell and its application data are not
part of the new packages.

## Scope

The shared shell, typography, status bar, input, brightness, application
discovery and process/display handoff are portable. Applications that depend on
Raspberry Pi camera/media interfaces or Debian services need their own backend
adaptation. The K230 image uses wpa_supplicant and SysV; installing this launcher
does not add NetworkManager, APT, systemd or Raspberry Pi utilities. Keep BSP
hardware services supplied by the K230 image; the independent network service
preserves Wi-Fi boot connectivity when the old shell is replaced.

The v0.2.9 BSP has no battery `power_supply` telemetry. Unknown battery charge
is shown as `--`; real battery percentage requires BSP driver/service support.
AppKit does not reproduce the old shell’s pinmux and GPIO manipulation.
