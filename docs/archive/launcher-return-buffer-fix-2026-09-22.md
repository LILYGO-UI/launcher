# 软件渲染下返回桌面重启修复

设备：`pi@192.168.8.206`，568×1232 屏幕。本文按主机日期记录；板端时钟
落后，故障日志时间为 2026-09-21 01:45–01:48。

## 故障与原因

设备实际运行的是软件渲染 Launcher，交接日志为 `retained=0`。应用退出码为
0，但恢复桌面时出现 `DRM render buffer allocation failed`，随后
`cannot restore drm display`，Launcher 以状态 1 退出并被 systemd 重启。
现场共记录 5 次自动重启；这条故障路径没有段错误或系统 OOM 的证据。

软件 DRM 旋转补丁每次创建显示时，都从 LVGL 固定 8 MiB TLSF 内存池分配
2,799,104 字节（568×1232×4）的整帧缓冲。显示销毁会释放缓冲，但字体缓存
会跨显示重建保留，新时钟数字等缓存分配使空闲区域碎片化。

使用实际 Launcher UI、字体和 PNG 图标的主机诊断程序可以复现：完成 3 次
切换后，第 4 次分配失败。当时总空闲为 8,353,104 字节，最大空闲块为
2,800,576 字节，碎片率 67%。TLSF 在这个大小档位按 65,536 字节分桶，
本次请求搜索的桶下限为 2,818,048 字节，因此仍无法满足分配。

## 修复

AppKit 的 `lvgl-9.5.0-drm-software-rotation.patch` 改为使用匿名
`mmap` 分配旋转缓冲，显示销毁时 `munmap`，使整帧缓冲独立于 LVGL 的
固定内存池。映射失败时清空指针并记录 errno，继续走已有的安全清理路径。
竖屏直接渲染不写入旋转缓冲，因此匿名页在需要使用时才提交。

修改同时保存在 Launcher 的 AppKit 子模块工作区及独立 AppKit 仓库。
应用身份、软件渲染模式和现有服务配置保持不变。

## 验证

- 主机诊断：原分配方式稳定复现失败；池外分配对照连续 60 次通过。
- 新增软件 DRM 回归测试：受限 LVGL 分配器下 64 次重建，覆盖三种旋转、
  切回竖屏、映射失败和初始化失败清理；旧补丁不通过，新补丁通过。
- AppKit 9/9 CTest 通过；Launcher 本机 8/8 CTest 通过。
- 改进硬件测试：横屏也重复应用启动/返回，真实应用测试支持软件渲染 Launcher。
- 设备实测：Files、Settings、Meshtastic、Template 各自横竖屏各 10 次上滑
  退出返回，共 80/80，通过首帧、进程存活和显示恢复检查。
- 修复前固定方向的轻量子进程测试也曾通过 20 次，说明仅短时间重复切换
  不足以排除受缓存内容影响的碎片问题。

真实应用测试使用隔离 XDG 目录、空 Files 目录及 Meshtastic 回环端口，
验证的是软件就绪和生命周期，不是物理显示像素或所有用户数据场景。

## 包与回退

修复包已安装到设备；安装后程序哈希与测试版一致，桌面首帧就绪，服务为
`active/running`，`ExecMainStatus=0`、`NRestarts=0`。

本次使用全新构建目录 `build/return-fix-arm64`。已有设备构建目录若缓存了旧的
LVGL 补丁源码，需要重新解包 LVGL 或使用新构建目录；不要直接复用旧补丁树。

修复包仍使用当前开发版本 `lilygo-ui-launcher_0.1.0_arm64.deb`。
通过 SHA-256 区分构建：

```text
修复包：b379f31ed31901706edb9cf619763182f32f8470d33131ab5965b1b3a58d20df
修复程序：9a812b5b8406f9ce0f2b66a41652d9e81dde56c6d831098d9d50ad06b4efa76f
原程序：1307520565fe1354b4ac115c9b126d4f827f205842b374a8e97a7e5182af1e17
```

板端旧包及旧程序备份目录：
`/var/backups/lilygo-ui/launcher-return-fix-20260922/`。
需要回退时安装其中的 `launcher-before.deb`。

本机材料位于 `build/launcher-return-fix-20260922/`，包含故障日志、主机诊断
程序与编译脚本、修复前后测试日志、80 次切换 JSONL、校验值、安装日志和包。
生产补丁与驱动回归测试位于 AppKit 源码，不依赖该诊断目录。
